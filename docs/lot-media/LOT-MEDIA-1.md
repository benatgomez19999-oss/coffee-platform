> Extended by [FARM-MEDIA-1](./FARM-MEDIA-1.md) — reusable farm-level
> media + producer media-readiness guard on verify/publish.
>
> Further extended by [LOT-MEDIA-2](./LOT-MEDIA-2.md) — visibility
> separation: `PUBLIC_MARKET` vs `BUYER_PRIVATE` vs `INTERNAL_ONLY`,
> public-only marketplace/catalog filtering, buyer-proof readiness
> helper.
>
> Further extended by [PARTNER-MEDIA-2A](./PARTNER-MEDIA-2A.md) —
> producer + partner CRUD endpoints, ownership checks, and a
> producer-facing media management page at `/platform/producer/media`.
>
> Rendered by [DASHBOARD-IMAGES-1](./DASHBOARD-IMAGES-1.md) — public
> media carousel for marketplace + client dashboard cards.

Production-ready data foundation for green-lot imagery. Each media row
carries a **role** (FARM / PROCESS / PRODUCER / …) so the ordered sequence
forms a documentary narrative rather than an opaque `images: string[]`
array. Backend / data / DTO plumbing only — no upload UI, no carousel,
no AI generation in this sprint.

## Schema

New Prisma enums + model (additive, no backfill):

```prisma
enum LotMediaRole {
  FARM
  PROCESS
  PRODUCER
  TRACEABILITY_BAG
  PRODUCT_DETAIL
  CERTIFICATE
  EDITORIAL_FALLBACK
}

enum LotMediaSource {
  PARTNER_UPLOAD
  PLATFORM_CURATED
  GENERATED_EDITORIAL
  TONAL_PLACEHOLDER
}

model GreenLotMedia {
  id          String  @id @default(uuid())
  greenLotId  String
  greenLot    GreenLot @relation(fields: [greenLotId], references: [id], onDelete: Cascade)

  url         String
  role        LotMediaRole
  source      LotMediaSource
  position    Int     @default(0)
  isPrimary   Boolean @default(false)

  altText     String?
  caption     String?
  credit      String?
  metadata    Json?

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@index([greenLotId])
  @@index([greenLotId, role])
  @@index([greenLotId, isPrimary])
}
```

`GreenLot` gains a single reverse relation `media GreenLotMedia[]`.
Existing lots have zero rows — the UI continues to fall back to the
deterministic tonal placeholder.

Migration: `prisma/migrations/20260511000000_add_lot_media_log/migration.sql`.

## Role semantics

| Role               | What it depicts                                            |
|--------------------|------------------------------------------------------------|
| `FARM`             | farm landscape, plot, altitude/origin environment          |
| `PROCESS`          | drying beds, washing station, fermentation, honey/natural  |
| `PRODUCER`         | producer, team, people/context                             |
| `TRACEABILITY_BAG` | sack, label, lot tag, shipment traceability photo          |
| `PRODUCT_DETAIL`   | cherry, green bean, roasted bean, sample, cup              |
| `CERTIFICATE`      | document/certificate, cupping sheet, lab proof             |
| `EDITORIAL_FALLBACK` | platform-curated or generated editorial visual           |

## Source trust model

The **source** field is the trust boundary, not the role:

- **`PARTNER_UPLOAD`** — uploaded by the partner who owns the lot.
  Documentary evidence; cards may render trust badges.
- **`PLATFORM_CURATED`** — curated by Altura Collective on the partner's
  behalf. Still considered verified documentary evidence.
- **`GENERATED_EDITORIAL`** — AI/illustrative imagery generated by the
  platform. **Not** documentary. The UI **must not** label this as a
  verified partner photo.
- **`TONAL_PLACEHOLDER`** — synthetic gradient placeholder. Same trust
  treatment as `GENERATED_EDITORIAL`.

`isVerifiedLotMediaSource(source)` returns true only for the first two.
`isFallbackLotMediaSource(source)` returns true for the last two.

A `FARM` row with source `GENERATED_EDITORIAL` does **not** satisfy a
"missing FARM" check — that's the whole point of `missingRecommendedRoles`.

## Ordering and primary selection

The pure helper `buildOrderedLotMedia(items)` returns a deterministic
view-model:

```ts
type OrderedLotMediaResult = {
  items: LotMediaItem[]
  primary: LotMediaItem | null
  hasVerifiedMedia: boolean
  hasPartnerMedia: boolean
  hasOnlyFallbackMedia: boolean
  missingRecommendedRoles: LotMediaRole[]
}
```

Ordering rules (`compareLotMediaItems`):

1. **Role priority** — FARM → PROCESS → PRODUCER → TRACEABILITY_BAG →
   PRODUCT_DETAIL → CERTIFICATE → EDITORIAL_FALLBACK.
2. **Position asc** within the same role.
3. **Id asc** as a stable tiebreak.

Primary selection (`selectPrimaryLotMedia`):

1. Any explicit `isPrimary=true` wins. If multiple primaries exist
   (data defect), the highest-priority role wins, then position, then id.
2. Otherwise the first item in the ordered list wins.
3. Empty input → `null`.

`missingRecommendedRoles` reports which of `RECOMMENDED_LOT_MEDIA_ROLES`
(currently `FARM / PROCESS / TRACEABILITY_BAG`) are not covered by a
**verified** row. Fallback rows do not count.

## DTO propagation

Every snapshot carries an optional `media: LotMediaItem[]` field which
the snapshot mapper populates from the new Prisma relation. From there:

- **`MarketplaceLotDto`** gains `media`, `primaryMedia`, `mediaSummary`.
  `visual.imageUrl` is also wired to `primaryMedia?.url ?? null` so
  single-image consumers (LotImageWell) keep working unchanged.
- **`ContractCatalogLotDto`** gains the same three fields. The client
  dashboard's catalog grid can opt in to using `primaryMedia.url`
  without touching the catalog mapper again.

All three new DTO fields are typed optional so existing test fixtures
and pre-LOT-MEDIA-1 API clients still satisfy the contract. Mapper
output always sets them — empty array / null / all-false summary when
the lot has no media rows.

## Alt-text helper

`buildDefaultLotMediaAltText({ lotName, variety, process, region, country, role })`
returns a deterministic alt string per role:

| Role               | Default                                                       |
|--------------------|---------------------------------------------------------------|
| FARM               | `<lotName> farm landscape in <region>, <country>`             |
| PROCESS            | `<process> processing for <lotName>`                          |
| PRODUCER           | `Producer of <lotName> in <region>, <country>`                |
| TRACEABILITY_BAG   | `Traceability label or bag for <lotName>`                     |
| PRODUCT_DETAIL     | `Coffee bean detail for <lotName>`                            |
| CERTIFICATE        | `Certificate or cupping sheet for <lotName>`                  |
| EDITORIAL_FALLBACK | `Illustrative image for <lotName>` (no documentary claim)     |

## What this sprint does NOT do

- No upload UI (file picker / drag-drop / partner dashboard).
- No storage integration (S3 / Supabase Storage / signed URLs).
- No AI image generation.
- No carousel / gallery UI.
- No lot detail page.
- No featured-media requirement enforcement.
- No dev seed media — existing dev factories are untouched. A future
  sprint can seed `TONAL_PLACEHOLDER` or `GENERATED_EDITORIAL` rows
  for visual exploration; **partner-upload rows must never be seeded
  synthetically**.

## Manual validation

After `npx prisma migrate deploy`:

1. `/dev/scenarios/lots` reset + seed `marketplace_mix`.
2. `/api/marketplace/lots` returns `media: []`, `primaryMedia: null`,
   `mediaSummary.hasVerifiedMedia=false` for every lot.
3. `/api/contracts/catalog` returns the same three fields.
4. In Prisma Studio, insert one row in `GreenLotMedia`:
   - any `greenLotId` from `marketplace_mix`
   - `role = FARM`
   - `source = PARTNER_UPLOAD`
   - `url = /images/marketplace_main_card.png` (or any safe local path)
   - `isPrimary = true`
5. Reload `/api/marketplace/lots` and confirm:
   - `primaryMedia.url` matches the inserted URL
   - `mediaSummary.hasPartnerMedia = true`
   - `visual.imageUrl` mirrors `primaryMedia.url`
6. Confirm publishing / contract / pricing behaviour is unchanged.
